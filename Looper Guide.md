# Looper — Developer Guide

Reference for improving Looper and planning features. Everything here reflects the
actual code at `~/Workspace/Apps/Looper` as of late September 2026 (v1.1.1,
build 31, post-`246515c` dead-code cleanup).

---

## 1. What Looper is

A minimal, native macOS video player built for one job: **open a local video file
instantly and loop it gaplessly, with as little UI as possible.**

- **Stack:** Swift 6, AppKit + AVFoundation. No SwiftUI, no third-party dependencies.
- **Shape:** Accessory app (`LSUIElement = true`, `.accessory` policy) — **never in
  the Dock**. Each open file gets its own window. The menu-bar status item is the
  app's only persistent UI.
- **Repo:** `github.com/RazorBackRoar/Looper` · MIT license · arm64 only ·
  macOS 14+ deployment target (targets modern macOS: glass UI on 26+).
- **Version:** `MARKETING_VERSION = 1.1.1`, `CURRENT_PROJECT_VERSION = 31`.
- **Bundle IDs:** Release `com.razorbackroar.looper`; Debug deliberately uses
  `com.razorbackroar.looper.debug` so Xcode/DerivedData builds can't hijack
  LaunchServices "Open With" registration; tests use `…looper.tests`.
- **Design workload:** ~6 simultaneous player windows is normal usage.
- **Machine context:** tuned for M5 Pro / 64 GB — instant playable start is the
  performance bar.

## 4. `VideoPlayer.swift` anatomy — the core file

One file holds the whole per-window implementation, top to bottom:

| Type | Kind | Role |
| ---- | ---- | ---- |
| `applyPlayerEDR` | func | Sets `preferredDynamicRange` (26+) / `wantsExtendedDynamicRangeContent` on the player layer — only when the clip is HDR |
| `PlayerWindowLayout` | enum, pure | All geometry constants + `fitVideoSize` / `contentSize` / `aspectCorrectedContentSize` |
| `PlayerTimelineMath` | enum, pure | `isLoopWrap` — wrap detection for full-clip and custom ranges |
| `PlayerLayerView` | view | Hosts `AVPlayerLayer`; display-only rotation (quarter-turns via `CATransform3D`); `videoGravity = .resizeAspectFill` |
| `VideoScrubBar` | view | Custom-drawn rail/thumb/loop markers; drag, scroll passthrough, double-click loop marks with click-sequence pair snapshot |
| `CircleControl` | view base | Drawn circles (not `NSButton`): hover/press alpha, VoiceOver button semantics, space/return activation |
| `SlomoButton` | `CircleControl` | Speed indicator — glyph shows `1`/`½` (the glyph IS the speed UI) |
| `InfoButton` | `CircleControl` | `info.circle` glyph; `isSelected` when inspector open |
| `VideoScrollView` | view | Scroll catcher over the picture + double-click surface; swallows single clicks (click never pauses) |
| `FileDropView` | view | Root content view; `.fileURL` drop target filtered to playable extensions |
| `MenuBarPlayerWindow` | `NSWindow` | Forces `.fullSizeContentView`, transparent titlebar, no separator; overrides `miniaturize` **and** `performMiniaturize` → `orderOut` + menu refresh (hides into menu bar, never the Dock) |
| `VideoPlayerWindowController` | `NSWindowController` | Everything else: boot, seeks, scrub, loops, keys, geometry, lifecycle (~1,500 lines, ~50 state vars) |

**Window layout:** content = `playerColumn` (video surface + `VideoScrollView`
overlay + 52 pt footer) | 1 pt separator | optional 300 pt `VideoInfoView`
inspector. The footer holds a 40 pt glass capsule (`NSGlassEffectView` `.clear` on
macOS 26+, `effectIsInteractive` on 27+; dark `NSVisualEffectView .hudWindow`
fallback) containing: elapsed `m:ss` · scrub bar · remaining `-m:ss` · speed
circle · info circle. All monospaced-digit labels, all custom drawing.

**Window chrome:** styleMask `.titled, .closable, .miniaturizable, .resizable` +
`.fullSizeContentView`; `titlebarAppearsTransparent = true`,
`titlebarSeparatorStyle = .none`, opaque black background. Title bar inset is
measured via `contentLayoutRect` (`titlebarInset`) and added back in
`frameRect(forVideoContentSize:)` everywhere a video-content size becomes a frame
size — inspector/separator start *below* the title area (`visibleTop` anchor).
Tabbing disallowed, `isReleasedWhenClosed = false`, `isRestorable = false`,
`animationBehavior = .none`, `.floating` level only while key (defeats Finder's
open-animation clip-through), `.moveToActiveSpace + .fullScreenAuxiliary`.

## 5. Lifecycle & open paths

```
Finder double-click ─┐
Open With ───────────┤   application(openFile[s]/urls)
argv (Terminal) ─────┼─► AppDelegate.openVideos(at:)
Drop on window ──────┤      │
Open Recent ─────────┘      ▼
                    LocalVideoURL.isPlayableFile gate
                    (file URL + mp4|mov|m4v|mkv only — remote URLs
                     never reach AVURLAsset; CWE-918 guard)
                           │
                    dedupe by standardizedFileURL.path
                    (re-open = focus existing window)
                           │
                    AssetCache.preload + WindowFrameStore.noteOpened
                    new VideoPlayerWindowController (cascade +30,−30)
```

- `AppDelegate` owns `windowControllers: [NSWindowController]` — retained until
  `windowWillClose` removes them.
- **Quit rules:** `applicationShouldTerminateAfterLastWindowClosed = false` (a
  hidden/minimized-to-menu-bar window must NOT quit the app); real close →
  `windowWillClose` → empty list → `NSApp.terminate`. Bare launch with no files
  self-terminates (skipped under XCTest via `XCTestConfigurationFilePath` check).
  `applicationShouldOpenUntitledFile`/`applicationShouldHandleReopen` both return
  false — no blank windows, ever.
- `applicationShouldTerminate` calls `AssetCache.cancelAllLoads`.

## 6. Playback engine

### Instant open (`bootPlayerFast`)

Five parallel `AssetCache` loads per window; reveal gates on three —
`loadPlayable` + `loadNativeSize` + `loadFrameRate` — via `tryAttachAndReveal`.
A **350 ms failsafe** forces the two flags so a slow probe can't wedge the window.
`loadDuration` and `loadContainsHDR` patch UI after reveal.

`slamOpaqueFront()` (opaque black, no animation, order front + key) runs at init,
on attach, and on failure — it covers Finder's thumbnail zoom instantly.

### Player stack (`attachPlayer`)

- `AVPlayerItem` — `preferredForwardBufferDuration = 30`,
  `seekingWaitsForVideoCompositionRendering = false`,
  `canUseNetworkResourcesForLiveStreamingWhilePaused = true`,
  `automaticallyPreservesTimeOffsetFromLive = false`
- `AVQueuePlayer` — `automaticallyWaitsToMinimizeStalling = false`,
  `actionAtItemEnd = .advance` (required for `AVPlayerLooper`; `.none` would pause
  at each loop → gap + thumbnail flash), `allowsExternalPlayback = false` (no
  AirPlay — deliberate)
- `AVPlayerLooper` — gapless full-clip loop on a template item; recreated for
  custom ranges
- `playImmediately(atRate: currentRate)` — starts at 1× immediately

### Playhead

`window.displayLink` at the monitor's refresh (`preferredFrameRateRange`
24…`maximumFramesPerSecond`; recreated on `windowDidChangeScreen`). The clip plays
at native fps; the link only drives the UI — 30 fps on 60 Hz holds 2:1, etc.

`playerTimeFired`: ignores updates during any scrub mode; honors
`pendingPlayheadSeconds` (holds knob until player catches up — 2-frame slop,
loop wrap, or 0.22 s timeout); rejects backward jitter unless it is a real wrap
per `PlayerTimelineMath.isLoopWrap` against `loopBounds` (custom range if active,
else whole clip). Knob redraw is skipped when it wouldn't move ≥1 px
(`lastKnobPixelX`).

### Seeks

Single-flight serialized (`seekInFlight`) with a coalesced queue — a second seek
overwrites `queuedSeekSeconds`, OR-accumulates the precise flag, and chains
completions. **30 seeks/s cap** (`maxSeekHz`) enforced at every call site;
`AVPlayer` can't absorb 120 Hz seeks. Coarse seeks use tolerance
`max(2·frameDuration, 50 ms)`; gesture-end seeks are zero-tolerance. After a
finished seek, a rate-0 player resumes at `currentRate` unless a pause-hold state
is active.

### Custom loop ranges

One state machine (`handleLoopPointInput`) serves both surfaces — double-click on
the video (marks at playhead) or on the scrub bar (marks at click point):
**pending point → complete pair (min span 0.1 s) → third double-click clears.**
Dragging the playhead outside an active range also clears it
(`clearCustomLoopIfOutside`). The scrub bar snapshots "pair existed" on the first
click of a sequence (`clickSequenceHadCompletePair`) so a scrub-outside first
click can't erase the intent a double-click needs.

`applyCustomLoop` serial-guards (`loopApplySerial`), disables the old looper,
precise-seeks to the in-point, creates `AVPlayerLooper(timeRange:)`, and caps the
in-flight item via `forwardPlaybackEndTime` so the out-point applies immediately.
Green range + markers draw under the thumb.

## 7. Input handling

All keyboard input goes through a per-window **local event monitor** that only
acts when that window is key. `isNonPlayerResponder` gives non-player responders
(circle controls, inspector, selectable text) their keys first; if focus left the
player mid-hold, active scrubs are released.

| Input | Behavior |
| ----- | -------- |
| **⌘Q** | Quit (app-level monitor + per-window handler) |
| **⌘M** | Hide window into menu-bar list (intercepted **before** plain `M` = mute) |
| **Space** | Play/pause |
| **M** | Volume-based mute (never `isMuted` — avoids audio-pipeline hitches) |
| **1** / **0** | Toggle ½× ↔ 1× / reset to 1× (silent — circle glyph is the indicator) |
| **L** | Rotate display 90° CCW (file unchanged; window refits) |
| **Return/Enter** | Close this window only |
| **← / →** hold | Hold-scrub: tap = small nudge; after ~0.16 s ramps to duration-scaled scan (0.22→1.0× clip-length/s) |
| **↑ / ↓** | Looper volume ±0.05 (not system volume) |
| **F7/F9** hold, **F8** | Same hold-scrub / play-pause as standard function keys |
| **Scroll on video** | up/right = forward, down/left = rewind; momentum ignored |
| **Scrub bar drag** | coarse seeks ≤30 Hz; precise seek + resume on release |
| **Double-click video/scrub bar** | loop-point state machine |
| **Drop files** | first replaces current clip; extras open new windows |

**Scroll-wheel details** (`PlaybackScrubMath` + `handleScrollWheel`): empty
`phase` = mouse — fixed **0.25 s/notch**, never duration-scaled; Magic Mouse
precise deltas accumulate at 8 px/notch, capped 0.45 s/event; mouse scrolls pause
playback during the gesture with a 180 ms end-debounce, then precise-seek +
resume. Trackpad (non-empty phase): duration-scaled — 4 % of clip per 150 px,
≤0.6 s/event — and **keeps playing** (no pause). Sub-0.4 px trackpad jitter and
small direction-reversal deltas are filtered.

**Shortcuts are gated:** `1`, `l`, `m`, space, return require an attached player
(`hasActivePlayback`) — they do nothing when Looper isn't playing video.

### Media keys (`MediaKeys`)

Two channels: `MPRemoteCommandCenter` (toggle/play/pause enabled; next/prev/skip
disabled) plus a `.systemDefined` **subtype-8** local monitor decoding raw HID
codes (`soundUp/Down/Mute/Play/Next/Prev/Fast/Rewind`). Holding Previous/Next
flips to Rewind/Fast — handled via key-down sets, a **0.28 s** tap-vs-hold
heuristic, and a **0.5 s** delayed end so the code-flip doesn't kill the scrub.
Volume nudges throttle at 40 ms; play toggles at 120 ms. Target = key window's
player, else last opened. Now Playing publishes title/elapsed/duration/rate (no
artwork).

## 8. Info inspector & metadata

- `i` circle → 300 pt right column + 1 pt hairline separator (`VideoInfoView`:
  `.sidebar` material). Opening widens the window — shifts left if needed, or
  shrinks the video to fit; closing restores the pre-open width unless the user
  resized/rotated meanwhile (`infoGeometryDirty`).
- `VideoMetadataSession` (@MainActor) is **lazy** — no extraction while hidden.
  Generation counter + URL + visibility guards kill stale publishes; a completed
  snapshot is reused on reopen. States: idle / loading / ready / partial /
  unavailable.
- `VideoMetadataReader` runs detached, returns a `Sendable` snapshot — no
  AVFoundation objects cross actors. Reads: File (name/format/size/dates/path —
  always), Recorded (embedded capture date), Camera (make/model/lens/focal/
  aperture/ISO/software — deduplicated), Location (**GPS: Yes/No only** — ISO 6709
  parsed for the flag; coordinates never displayed), Video (duration/display
  resolution/fps/bit rate/codec/encoded dims/color), Audio (codec/sample
  rate/channels/language/bit rate), plus a bounded **More Details** disclosure
  (≤256 fields, ≤2048 chars each, deduped, source-labeled).
- `ISO6709LocationParser` handles Apple's decimal form (`+37.3348-122.0090+063.1/`),
  fixed-width DDMM.MM/DDDMM.MM and DDMMSS.SS/DDDMMSS.SS; range-validates
  lat ≤90 / lon ≤180, minutes/seconds <60.
- `VideoInfoView` renders a **fixed schema** — every expected row always shows,
  `N/A` when absent; identical states don't rebuild the view tree.
- Codec labels map FourCCs → names (H.264, HEVC, AV1, VP9, ProRes, Dolby Vision,
  AAC, AC-3/E-AC-3, ALAC, FLAC, Opus, PCM, MJPEG, H.263…).

## 9. Menu bar / status item

- `NSStatusItem` (square, `repeat` SF Symbol template, tooltip "Looper") exists
  only while windows are open; removed on quit.
- Menu = **Windows** section (each player's title; hidden windows suffixed
  "(Hidden)"; checkmark on key window; click → restore/focus) + **Open Recent**
  (≤12, existing files only) + **Quit Looper ⌘Q**.
- `rebuildStatusMenu` runs on open/close/focus/hide — `refreshWindowMenu` is the
  public entry used by `MenuBarPlayerWindow.miniaturize` and
  `windowDidBecomeKey`.
- Main menu (invisible in an accessory app but needed for key equivalents):
  Looper (About, Quit ⌘Q) · File (Open Recent) · Window (Close ⌘W, **Minimize to
  Menu Bar ⌘M** — routes to `performMiniaturize` → the same hide path as the
  yellow button · Bring All to Front). `NSApp.windowsMenu` is set, so AppKit also
  appends live window items (`isExcludedFromWindowsMenu = false`).

### Hide-to-menu-bar behavior (recent change)

`MenuBarPlayerWindow` overrides both `miniaturize(_:)` (the actual yellow-button
selector) and `performMiniaturize(_:)` (menu/⌘M) to `orderOut` + refresh the
status menu. The controller stays alive — **playback and audio continue while
hidden**; selecting the title in the menu restores via `makeKeyAndOrderFront`.
`isMiniaturized` is never set, so nothing appears above the Dock trash.

## 10. Caching & persistence

| Store | Where | Policy |
| ----- | ----- | ------ |
| `AVURLAsset` | `NSCache` | count 128, cost ~1 GB @ 8 MB/entry; created with `AVURLAssetPreferPreciseDurationAndTimingKey` |
| Native sizes | `NSCache` + `UserDefaults` `Looper.nativeSizes` | persists `"WxH"` strings, trims 400→300 — instant window sizing on reopen |
| fps / HDR | `NSCache` | memory only |
| Window frames | `UserDefaults` `Looper.windowFrames` + `…Order` | per-path `NSStringFromRect`, LRU 400→300 |
| Recents | same order array | newest-first, max 12, filters nonexistent files |
| Legacy keys | `Looper_WindowFrame_*` | one-shot migration via `Looper.windowFrames.migrated` |

All loads go through a `loadTasks[key][id]` registry under `NSLock` —
`cancelLoads(for:)` on replace/close, `cancelAllLoads` on terminate; every load
checks `Task.isCancelled` between awaits. `AssetCache`/`WindowFrameStore` expose
swappable `defaults` (tests inject per-suite `UserDefaults`).

**Everything is keyed by `standardizedFileURL.path`** — rename/move a file and
its frame/recents/cache entries become orphans (they get trimmed eventually).

## 11. HDR/EDR & display

`loadContainsHDR` checks `.containsHDRVideo`, then format-description transfer
functions (PQ / HLG). `applyPlayerEDR` sets `preferredDynamicRange = .high`
(macOS 26+) or `wantsExtendedDynamicRangeContent` — **only for HDR clips**; SDR
never gets EDR. On a non-EDR / non-HDR display, macOS Core Animation
automatically tone-maps HDR content down to the display's SDR range — the video
plays normally, you just don't get extended brightness. `videoGravity =
.resizeAspectFill` + aspect-locked window = no letterbox bars, ever.
`NSSupportsAutomaticGraphicsSwitching = false` in the plist keeps the
high-performance path pinned.

## 13. Build, packaging, CI

`./scripts/build-mac.sh` (bash, `set -euo pipefail`):

1. Removes stale `build/Release/Looper.{app,dmg}` and any stray repo `Looper.app`
   (named paths — `razorbuild` runs it under zsh where unmatched globs error).
2. Icon: `uv run --with pillow python scripts/generate-icon.py`
   (`LOOPER_ICON_PYTHON` override; falls back to committed `Looper.icns`).
   The script isolates the squircle from `IconSource.png`'s baked checkerboard
   (chroma/luminance mask → corner floodfill → center-component keep → 1 px
   erode), scales to the **824×824** grid on a 1024 canvas, adds the shared
   drop shadow (blur 5, offset +10, α80 — identical to MetaBurn/Libra), writes
   asset-catalog PNGs + `Looper.icns` via `iconutil`.
3. `xcodebuild -configuration Release -arch arm64 -derivedDataPath build/DerivedData
   ONLY_ACTIVE_ARCH=NO build`.
4. Stage `.app` → overlay `Looper.icns` → `.razorcore/patch-app-branding.sh`
   (copyright stamp) → `codesign` (ad-hoc; `LOOPER_SIGN_IDENTITY` switches to
   Developer ID + `--options runtime` + verify) → `.razorcore/package-dmg.sh`
   (locked layout: 500×420 window, 128 px icon, app at (130,160), Applications
   link (370,160)) → `build/Release/Looper.dmg`.
5. `package-dmg.sh` calls `.razorcore/desktop-dmg-copy.sh`, which copies
   `build/Release/Looper.dmg` → `~/Desktop/Looper.dmg` on local builds (skipped
   when `CI`/`GITHUB_ACTIONS`/`RAZORCORE_SKIP_DESKTOP_DMG` is set). Staging
   `.app` and `build/DerivedData` are deleted.

**CI** (`.github/workflows/ci.yml`, job `quality`, `macos-26`): Release build +
test, `CODE_SIGN_IDENTITY=-`, concurrency cancels in-progress runs. No DMG, no
lint step. **Dependabot** watches `github-actions` only (weekly, grouped
minor+patch, ≤3 open PRs) — there are no Swift dependencies to manage.

`scripts/install-to-applications.sh` — manual opt-in: `pkill -x Looper`,
replace `/Applications/Looper.app`, overlay icns, ad-hoc re-sign,
`xattr -cr` (strip quarantine so Open With works), `lsregister -f`. **Not** wired
into the build.

The macOS `quality` workflow is the build that matters. Ubuntu CI cannot
exercise AppKit or AVFoundation.

## 15. Known limitations & deliberate constraints

**Deliberate (product invariants — don't "fix" these):**

- No Dock presence, ever. No blank/untitled windows. No window-open animations.
- Click on video never pauses. No on-screen volume slider. No speed HUD.
- Local files only — remote URLs are rejected before asset creation.
- GPS only ever surfaces as `GPS: Yes`/`GPS: No` — no map, no coordinates.
- `allowsExternalPlayback = false` — no AirPlay/external playback UI.
- Timeline never overlays the picture; speed changes are silent.

**Real limitations / gaps:**

- **MKV registered but usually unplayable** — AVFoundation can't decode Matroska;
  failure only retitles the window (`Can't play MKV — name`), no alert. Either
  drop the registration or add a real error path.
- **No fullscreen** — `.fullScreenAuxiliary` lets the window float over
  fullscreen spaces but green-button fullscreen isn't enabled.
- **No subtitles/captions** — nothing selects legible tracks on the player item.
- **No audio-track selection, no chapters, no frame-step keys, no screenshots,
  no picture-in-picture.**
- **Speed is only 0.5×/1×** — no other rates, no pitch correction handling.
- **Hidden windows keep playing audio** — intended behavior: hiding stops the
  picture only; audio continues at the window's current volume/mute until the
  window is restored or closed.
- **Rotation is per-session** — not persisted per file (loop ranges aren't
  either).
- **Everything keys on file path** — moves/renames lose frames/recents/cache.
- **Edge case:** on a failed-load window (e.g. MKV), `isLooperPlaybackShortcut`
  includes Return (keyCode 36/76), and the `!hasActivePlayback` gate causes
  `handleKey` to pass the event through to AppKit, where nothing catches it —
  so Return silently does nothing. Only red button/⌘W works there.
- **Ad-hoc signing** — Gatekeeper friction on first open is expected;
  `LOOPER_SIGN_IDENTITY` exists for Developer ID but isn't used by default.

**Dead code — cleaned:** the unused `AssetCache` poster cache
(`storePoster`/`cachedPoster`, 64-entry NSCache), the write-only `didReveal`
flag, the redundant per-window ⌘Q path (the app-level monitor covers it — and
only *plain* ⌘Q quits now, so ⌘⇧Q/⌘⌥Q/⌘⌃Q no longer kill the app), and the
uncalled `PlaybackFormatting.formatRate` were all removed. Remaining:

## 17. Invariants — do not break when editing

1. Accessory app; never in the Dock. Yellow/⌘M hides into the menu-bar list
   (picture hidden; audio keeps playing at the window's current volume/mute);
   only closing the last player window quits. No persistence agents.
2. Click on the video never pauses; Space toggles play/pause;
   Return closes only the key window; ⌘Q quits.
3. Timeline lives in the footer capsule — never overlays the picture.
4. No on-screen volume slider; speed changes are silent (circle glyph only).
5. Shortcuts act only while a Looper window is key; non-player responders keep
   their keys. ⌘M must be handled before plain `M` (mute).
6. Video fills the window at clip aspect; the video region (not the whole
   window) aspect-locks on resize; footer/inspector are separate chrome.
7. Clip plays at native fps; playhead rides the display link; ≤30 seeks/s;
   coarse during gestures, precise at end; trackpad scrub is duration-scaled,
   mouse never is; momentum ignored; playback resumes after scrub.
8. Reveal only after size + fps + playable resolve (350 ms failsafe); opaque
   black covers Finder's zoom; `.floating` only while key.
9. Local file URLs only — nothing remote reaches `AVURLAsset`.
10. GPS surfaces only as `GPS: Yes`/`GPS: No` — no map, no coordinates.
11. Per-file frame memory + recents, capped; per-clip state fully resets on

    - no separator) — all frame math must route through `titlebarInset` /

## 19. Task to do

with both the keyboard and mouse.

### New keyboard controls

| Key | Action |
| --- | ------ |
| **A** | Slow motion — toggle ½× ↔ 1× (same behavior as the current `1` key / `toggleHalfSpeed()`) |
| **D** | Toggle pause / play (same behavior as the current Space / `togglePlayPause()`) |
| **S** | Rewind (hold-scrub backward — same behavior as current ← arrow hold) |
| **F** | Fast-forward (hold-scrub forward — same behavior as current → arrow hold) |
| **G** | Toggle loop creation (see loop workflow below) |

These new keys **add to** the existing controls — arrow keys, scroll, scrub bar
drag, double-click loop marks, `M` (mute), `L` (rotate), `0` (reset speed),
Return (close), ⌘M (hide), ⌘Q (quit) all remain unchanged.

Remove F7/F8/F9 standard function-key handling from `handleKey` — no F-keys in
Looper. Hardware media keys (play/pause/skip via `MediaKeys.swift` system-defined
events) still work.

### G-key loop workflow

The `G` key makes loop creation extremely quick:

1. Play a video normally.
2. Press **G** to set the first loop marker at the current playhead position.
3. Use **F** to fast-forward through the video if needed (works whether
   paused or playing).
4. Press **G** again to set the second loop marker — the section between
   the two G presses becomes the active loop.
5. Press **G** again to clear the loop and begin/reset the loop-selection
   process for another loop.

This is the same three-state machine as the existing double-click loop path
(`handleLoopPointInput`: pending point → complete pair → clear), but triggered
by a single key press at the current playhead instead of a double-click at a
screen position. `G` should call `loopPointAtCurrentTime()` on each press.

### Implementation rules

- All new keyboard controls must work regardless of whether the video is
  currently paused or playing, wherever that makes sense.
- Keyboard shortcuts and mouse controls must operate through the **same
  underlying actions** so there is no difference in behavior between the
  two input methods.
- Keep the existing UI and functionality intact unless changes are necessary
  to support this workflow.
- New keys (`a`, `d`, `s`, `f`, `g`) must be gated by `hasActivePlayback`
  the same way existing playback shortcuts are.
- `S` and `F` should use the same `startHoldScrub(forward:)` /
  `stopHoldScrub()` path as the arrow keys (keyDown starts, keyUp stops).
- `G` calls `loopPointAtCurrentTime()` — the existing method that marks at
  the current playhead and feeds the three-state loop machine.
- Add the new keys to `isLooperPlaybackShortcut` so the `hasActivePlayback`
  gate applies.
- Update the `arrowHoldKeys` / hold-scrub tracking to also track `S`/`F`
  keyUp releases, so hold-scrub stops when the key is released.
